📚 Comentarios del Código - Explicaciones

Documento que responde a las preguntas e instrucciones encontradas en los comentarios del código.

1. Importación de estilos globales en layout.tsx

Ubicación: app/layout.tsx

Comentario original:

// Hay que importar siempre los estilos que vienen ya predefinidos para que se apliquen al archivo que queramos y empiece a coger forma

Explicación:

En Next.js, los estilos CSS globales deben importarse en el Layout raíz (app/layout.tsx), no en componentes individuales.

❓ ¿Por qué funciona así?

Next.js utiliza un modelo de estilos globales centralizados:

  • Los estilos se importan en el lugar más alto de la jerarquía de componentes
  • El layout.tsx actúa como el contenedor raíz de toda la aplicación
  • Todos los componentes heredan estos estilos

⚠️ Consecuencia:

Si importas CSS global en page.tsx o en otros componentes, causará un error de build porque Next.js no permite importar CSS global desde múltiples lugares (podría haber conflictos).

2. Por qué los estilos globales solo aplican al Layout

Ubicación: app/ui/global.css

Comentario original:

/* Aquí podemos añadir estilos que apliquen a toda la página. Explica por qué solo aplica al layout y por qué si lo importo en el page.tsx no se aplica el estilo */

✅ ¿Por qué aplica en el Layout?

El layout.tsx es el componente raíz que envuelve todo:

export default function RootLayout({ children, }: { children: React.ReactNode; }) { return ( <html lang="en"> <body> {/* Aquí va el children (page.tsx, otros componentes, etc.) */} {children} </body> </html> ); }

Los estilos importados aquí se aplican a todo el HTML que renderiza, incluyendo los children.

✅ ¿Puedo importar CSS global en page.tsx?

Sí, es posible. A diferencia de lo que se creía anteriormente, Next.js permite importar CSS global en componentes como page.tsx, especialmente en versiones recientes.

Esto funciona porque page.tsx sigue siendo parte del árbol de componentes que se renderiza, aunque es recomendable centralizarlo en el Layout para mejor organización.

🎯 Solución: Cómo aplicar estilos específicos a page.tsx

Si quieres estilos específicos para page.tsx, tienes varias opciones:

1. CSS Modules (estilos locales):

import styles from "./page.module.css"; export default function Page() { return <h1 className={styles.title}>Home</h1>; }

2. Tailwind CSS (con clases de utilidad):

export default function Page() { return <h1 className="text-2xl font-bold">Home</h1>; }

3. Estilos inline:

export default function Page() { return <h1 style={{ fontSize: "2rem", fontWeight: "bold" }}>Home</h1>; }

📊 Jerarquía de estilos en Next.js:

app/layout.tsx └── import './ui/global.css' ✅ CSS Global (aplica a todo) └── app/page.tsx └── import './page.module.css' ✅ CSS Local (solo para page) └── className="tailwind-class" ✅ Tailwind (solo para página) └── style={{...}} ✅ Inline (solo para página)

📌 Resumen - Reglas Clave

Regla Descripción
CSS Global en Layout ✅ Se importa en app/layout.tsx
CSS Global en otros archivos ✅ También es posible (aunque mejor centralizarlo en Layout)
CSS Modules ✅ Se usan en componentes específicos (.module.css)
Tailwind/Inline ✅ Se usan directamente en componentes

3. CSS Modules: Estilos Locales para Componentes

Ubicación: app/page.module.css y app/page.tsx

¿Qué son los CSS Modules?

Los CSS Modules son archivos CSS que se importan como objetos JavaScript en componentes React. Cada clase CSS se convierte en una propiedad del objeto, garantizando que los estilos sean locales al componente (no globales).

Ventaja principal: Los nombres de clase se "scopean" automáticamente, evitando conflictos de nombres entre componentes.

📝 Implementación práctica en la home

1. Crear archivo page.module.css:

.homeContainer { display: flex; flex-direction: column; min-height: 100vh; padding: 1.5rem; } .headerBox { display: flex; height: 5rem; align-items: flex-end; border-radius: 0.5rem; background-color: #3b82f6; padding: 1rem; margin-bottom: 1.5rem; } @media (min-width: 768px) { .headerBox { height: 13rem; } } .leftSection { display: flex; flex-direction: column; justify-content: center; gap: 1.5rem; border-radius: 0.5rem; background-color: #f3f4f6; padding: 2.5rem 1.5rem; } .welcomeText { font-size: 1.25rem; color: #1f2937; } .welcomeLink { color: #3b82f6; text-decoration: none; font-weight: 500; } .loginButton { display: flex; align-items: center; gap: 1.25rem; border-radius: 0.5rem; background-color: #3b82f6; padding: 0.75rem 1.5rem; color: white; text-decoration: none; transition: background-color 0.2s ease; } .loginButton:hover { background-color: #60a5fa; }

2. Importar en page.tsx:

import styles from './page.module.css'; export default function Page() { return ( <main className={styles.homeContainer}> <div className={styles.headerBox}> {/* Contenido */} </div> <div className={styles.contentWrapper}> <div className={styles.leftSection}> <p className={styles.welcomeText}> Bienvenido </p> <a className={styles.welcomeLink}>Link</a> <button className={styles.loginButton}> Log in </button> </div> </div> </main> ); }

🔍 ¿Cómo funciona bajo el capó?

Cuando compilas el proyecto, Next.js transforma el CSS Module:

// Lo que defines en page.module.css: .homeContainer { ... } .headerBox { ... } // Se convierte en: // styles.homeContainer = "page_homeContainer__abc123" // styles.headerBox = "page_headerBox__def456" // En el HTML final: <main className="page_homeContainer__abc123"> </main>

Los nombres de clase se hacen únicos globalmente con un hash automático, garantizando que no haya conflictos incluso si otro componente usa .homeContainer.

⚖️ CSS Modules vs Tailwind vs CSS Global

Método Ámbito Caso de uso
CSS Global 🌍 Global (toda la app) Reset, variables, tipografía base
CSS Modules 🏠 Local (componente) Estilos complejos específicos
Tailwind CSS ✨ Clases de utilidad Estilos rápidos y componentes simples
Inline styles 🎯 Específico Estilos dinámicos basados en datos

✅ Ventajas de CSS Modules

  • Sin conflictos de nombres: No importa si otros componentes usan las mismas clases
  • Fácil de mantener: Los estilos viajan con el componente
  • Seguridad de tipos: Si borras una clase, el IDE lo detecta
  • Mejor rendimiento: Solo carga los estilos necesarios para cada página

❌ Consideraciones

  • No puedes usar pseudoelementos globales (necesitan CSS global)
  • Requiere más código que Tailwind para estilos simples
  • Menor reutilización de estilos entre componentes

4. Implementación de Google Fonts: Montserrat

Archivos modificados:

  • app/ui/fonts.ts - Configuración de fuentes
  • app/layout.tsx - Importación y uso

Cómo se implementó:

1. Crear app/ui/fonts.ts:

import { Montserrat } from 'next/font/google'; export const montserrat = Montserrat({ subsets: ['latin'], weight: ['400', '500', '600', '700', '800'], variable: '--font-montserrat', });

2. Importar en app/layout.tsx:

import { montserrat } from './ui/fonts'; export default function RootLayout({ children }) { return ( <html lang="en" className={montserrat.className}> <body>{children}</body> </html> ); }

¿Qué hace cada parte?

  • import { Montserrat } from 'next/font/google' - Trae la fuente desde Google Fonts
  • weight: ['400', '500', '600', '700', '800'] - Especifica qué pesos (grosores) descargar
  • subsets: ['latin'] - Optimiza descargando solo caracteres latinos
  • className={montserrat.className} - Aplica la fuente a todo el HTML

🔍 Autocomplete para localizar fuentes

¿Sabías que hay autocomplete? Cuando importas desde next/font/google, tu editor (VS Code) tiene soporte para autocomplete. Simplemente escribe parte del nombre de la fuente deseada y el IDE te mostrará una lista de opciones disponibles en Google Fonts. Esto hace muy fácil encontrar y seleccionar la fuente perfecta sin necesidad de consultar documentación externa.

Ejemplo de autocomplete:

// Empieza a escribir: import { /* Aquí sale autocomplete */ // Si escribes "Rob" verás: // - Roboto // - Roboto Condensed // - Roboto Flex // - Roboto Mono // - Roboto Serif // etc.
La fuente se descarga automáticamente desde Google Fonts y se sirve optimizada. No necesitas archivos locales ni visitar sitios externos para buscar fuentes.

5. Componente Image de Next.js vs HTML <img>

Ubicación: app/ui/invoices/table.tsx

¿Qué es el componente Image?

Next.js proporciona un componente <Image> optimizado que reemplaza al elemento HTML <img> estándar. Es una evolución que trae múltiples mejoras de rendimiento y funcionalidad.

🖼️ Diferencias principales

1. HTML img normal:

<img src="/customers/avatar.png" alt="Customer avatar" width="32" height="32" />

2. Next.js Image component:

import Image from 'next/image'; <Image src="/customers/avatar.png" alt="Customer avatar" width={32} height={32} />

⚡ Ventajas de usar Image

Característica <img> normal <Image> de Next.js
Optimización automática ❌ No ✅ Sí, convierte a WebP, avif
Carga responsiva ❌ Carga toda la imagen ✅ Carga diferentes tamaños según el dispositivo
Lazy loading automático (carga solo cuando la imagen se ve en pantalla) ❌ Necesita JavaScript ✅ Nativo, no necesita JS
Prevención de Layout Shift ❌ Puede desplazar el contenido ✅ Requiere width/height para evitar cambios
Caché automático ❌ Gestión manual ✅ Integrada en Next.js
Blur placeholder ❌ No disponible ✅ Opción blurDataURL para efecto blur

🎯 Ejemplo práctico con propiedades

import Image from 'next/image'; export default function CustomerAvatar({ imageUrl, name }) { return ( <Image src={imageUrl} alt={`Avatar de ${name}`} width={40} height={40} className="rounded-full" priority={false} placeholder="blur" blurDataURL="data:image/jpeg;base64,..." /> ); }

📋 Propiedades importantes de Image

  • src - Ruta de la imagen (puede ser URL externa)
  • alt - Texto alternativo (obligatorio para accesibilidad)
  • width y height - Dimensiones obligatorias (previenen Layout Shift)
  • priority - Si es true, carga la imagen antes que otras (útil para imágenes "above the fold")
  • placeholder - Puede ser "blur" o "empty" para mostrar algo mientras carga
  • quality - Calidad de la imagen (1-100), por defecto 75
  • fill - Alterna a true si quieres que ocupe un contenedor padre

⚠️ Cuándo usar cada uno

Usa <Image> de Next.js cuando:
  • Necesitas optimización automática
  • La imagen aparece en múltiples páginas
  • Quieres mejorar el Core Web Vitals (LCP, CLS)
  • Trabajas con imágenes en formatos antiguos (JPG, PNG)
Puedes usar <img> cuando:
  • Necesitas un SVG (no necesita optimización)
  • Es una imagen dinámica generada en tiempo real
  • Requieres máxima flexibilidad sin restricciones de Next.js
Recomendación: Prefiere siempre <Image> en Next.js. Es mejor para el rendimiento y está optimizado automáticamente. Solo usa <img> cuando tengas una razón específica.

6. Enrutado Basado en el Sistema de Archivos (File-based Routing)

¿Qué es el file-based routing?

Next.js utiliza un sistema de enrutado automático basado en la estructura de carpetas y archivos dentro de la carpeta app. No necesitas configurar rutas manualmente como en otros frameworks (Express, etc.). La carpeta define la ruta URL.

Regla de oro: Cada carpeta en app se convierte en un segmento de la ruta URL, y los archivos page.tsx son los que renderizan la página.

📁 Estructura de carpetas = Rutas URL

app/ ├── page.tsx ➜ GET / ├── about/ │ └── page.tsx ➜ GET /about ├── products/ │ └── page.tsx ➜ GET /products │ └── [id]/ │ └── page.tsx ➜ GET /products/:id (dinámico) └── dashboard/ ├── layout.tsx ➜ Layout específico para /dashboard y sus hijos ├── page.tsx ➜ GET /dashboard ├── invoices/ │ ├── page.tsx ➜ GET /dashboard/invoices │ └── [id]/ │ └── page.tsx ➜ GET /dashboard/invoices/:id └── customers/ └── page.tsx ➜ GET /dashboard/customers

🎯 Ejemplo práctico: Ruta /dashboard

1. Crear la estructura de carpetas:

app/ └── dashboard/ ├── layout.tsx (opcional: layout específico del dashboard) └── page.tsx (la página que se renderiza en /dashboard)

2. Contenido de app/dashboard/page.tsx:

import { Card } from '@/app/ui/dashboard/cards'; import { LatestInvoices } from '@/app/ui/dashboard/latest-invoices'; export default function DashboardPage() { return ( <main> <h1>Dashboard</h1> <div className="grid grid-cols-4 gap-4"> <Card title="Total Revenue" value="$45,231" /> <Card title="Pending Invoices" value="12" /> <Card title="Total Customers" value="348" /> </div> <LatestInvoices /> </main> ); }

3. Acceder a la página:

// URL en el navegador: http://localhost:3000/dashboard // Desde el código (con Link de Next.js): import Link from 'next/link'; export default function Nav() { return ( <nav> <Link href="/dashboard"> Dashboard </Link> </nav> ); }

📂 Convenciones especiales en Next.js

Archivo Propósito Ejemplo
page.tsx La página principal de la ruta app/dashboard/page.tsx ➜ /dashboard
layout.tsx Layout compartido para esa ruta y sus hijas app/dashboard/layout.tsx envuelve /dashboard y subcarpetas
[id] Segmento dinámico (parámetro de ruta) app/products/[id]/page.tsx ➜ /products/123
[...slug] Segmento dinámico que captura múltiples niveles app/docs/[...slug]/page.tsx ➜ /docs/guides/intro
route.ts Endpoint de API REST app/api/users/route.ts ➜ POST /api/users

🏗️ Estructura típica de un proyecto

app/ ├── layout.tsx (Layout raíz - envuelve toda la app) ├── page.tsx (Página home: /) ├── dashboard/ │ ├── layout.tsx (Layout del dashboard) │ ├── page.tsx (/dashboard) │ ├── invoices/ │ │ ├── page.tsx (/dashboard/invoices) │ │ ├── [id]/ │ │ │ └── page.tsx (/dashboard/invoices/123) │ │ └── create/ │ │ └── page.tsx (/dashboard/invoices/create) │ └── customers/ │ ├── page.tsx (/dashboard/customers) │ └── [id]/ │ └── page.tsx (/dashboard/customers/456) ├── login/ │ └── page.tsx (/login) ├── api/ │ ├── users/ │ │ └── route.ts (GET/POST /api/users) │ └── invoices/ │ └── [id]/ │ └── route.ts (GET/PUT /api/invoices/123) └── ui/ └── (componentes compartidos, no generan rutas)

✨ Ventajas del file-based routing

  • Intuitivo: La estructura de carpetas refleja directamente las rutas
  • Escalable: Fácil agregar nuevas páginas solo creando carpetas
  • Sin configuración: No necesitas archivos de configuración de rutas
  • Colocación de archivos: Puedes poner CSS modules, componentes cerca de la página
  • Layouts anidados: Cada carpeta puede tener su propio layout

6.1 - Subrutas: Truco para crearlas rápidamente

Una subruta es una ruta anidada dentro de otra. Por ejemplo, /dashboard/customers es una subruta de /dashboard. Aquí viene un truco muy útil:

¿Sabías este truco de VS Code? En VS Code, puedes crear un archivo con una ruta que no existe aún. El editor creará automáticamente todas las carpetas intermedias. Por ejemplo, si haces clic derecho en la carpeta app/dashboard y eliges "New File", puedes escribir:

customers/page.tsx

VS Code creará automáticamente la carpeta customers y dentro el archivo page.tsx, ¡sin necesidad de crearlas manualmente!

Ejemplo: Crear /dashboard/customers

app/ └── dashboard/ ├── page.tsx (/dashboard) └── customers/ └── page.tsx (/dashboard/customers) ← NUEVA SUBRUTA

Cómo usar el truco:

  1. Haz clic derecho en la carpeta donde quieres crear el archivo (ej: app/dashboard)
  2. Selecciona "New File"
  3. Escribe la ruta completa: customers/page.tsx
  4. Presiona Enter
  5. VS Code crea automáticamente la carpeta y el archivo
Funciona también para rutas más profundas:
customers/[id]/edit/page.tsx
VS Code crea todas las carpetas intermedias automáticamente.
Pro tip: Usa la carpeta (grupo) con paréntesis para organizar rutas sin afectar la URL. Ejemplo: app/(auth)/login/page.tsx sigue siendo /login pero está organizado bajo "auth".
